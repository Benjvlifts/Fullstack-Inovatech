GUÍA DE DESPLIEGUE - INNOVATECH SOLUTIONS (BACKEND)
==================================================

Sigue este orden exacto para que todo funcione correctamente en una nueva PC.

1. REQUISITOS PREVIOS
---------------------
Asegúrate de tener instalado en la PC de la U:
- PostgreSQL 15+ (y pgAdmin 4).
- Java JDK 21.
- Maven 3.9+.
- Node.js 18+.
- Postman.

2. PREPARACIÓN DE LA BASE DE DATOS (PostgreSQL)
-----------------------------------------------
Antes de ejecutar el código, debes tener las bases de datos listas:
1. Abre pgAdmin 4.
2. Crea una base de datos llamada: innovatech_auth_db
3. Crea otra base de datos llamada: innovatech_proyectos_db

*Si llevas un respaldo (.sql o .backup), haz clic derecho en la DB -> 'Restore' y selecciona el archivo.

3. CONFIGURACIÓN DE MICROSERVICIOS (Java)
-----------------------------------------
En cada microservicio (ms-auth y ms-proyectos):
1. Ve a: src/main/resources/application.properties
2. Verifica/Cambia los siguientes datos según la PC de la U:
   - spring.datasource.username=postgres
   - spring.datasource.password=PON_AQUÍ_LA_CLAVE_DE_POSTGRES_DE_LA_U
   - server.port=8081 (para ms-auth)
   - server.port=8082 (para ms-proyectos)
3. En la terminal de cada carpeta ejecuta:
   $ mvn clean spring-boot:run

4. CONFIGURACIÓN DEL BFF (Node.js)
----------------------------------
1. Entra a la carpeta: innovatech-bff-valdes-munoz
2. Crea/Edita el archivo .env en la raíz (asegúrate que no tenga extensión .txt):
   PORT=3000
   MS_AUTH_URL=http://localhost:8081/api/auth
   MS_PROYECTOS_URL=http://localhost:8082/api/projects
3. En la terminal ejecuta:
   $ npm install
   $ node src/index.js
   *Deberías ver: ms-auth -> http://localhost:8081/api/auth (no debe decir undefined)

5. FLUJO DE PRUEBAS EN POSTMAN
------------------------------
Probar siempre al puerto 3000 (BFF):

Paso 1: POST http://localhost:3000/api/auth/register
   - Body JSON: {"name": "Test", "email": "test@u.cl", "password": "123", "role": "ADMIN"}

Paso 2: POST http://localhost:3000/api/auth/login
   - Body JSON: {"email": "test@u.cl", "password": "123"}
   - COPIA EL TOKEN RECIBIDO.

Paso 3: POST http://localhost:3000/api/projects
   - Headers: Authorization -> Bearer PEGA_AQUÍ_EL_TOKEN
   - Body JSON: {"name": "Proy U", "description": "Desc", "type": "SOFTWARE", "status": "IN_PROGRESS"}

Paso 4: GET http://localhost:3000/api/projects/1
   - Headers: Authorization -> Bearer TOKEN

6. PRUEBA DE RESILIENCIA (CIRCUIT BREAKER)
------------------------------------------
1. Con todo funcionando, apaga el microservicio de proyectos (Ctrl+C).
2. Haz el GET de proyectos en Postman 5 veces.
3. El BFF responderá 503 "Service Unavailable" y el circuito quedará OPEN.
4. Consulta http://localhost:3000/health para mostrar el estado.
